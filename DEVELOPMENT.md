# Как устроен Kinodom

Здесь описано, где что лежит и как части связаны. Сборка и тесты — в [BUILD.md](BUILD.md).

## Целиком

Kinodom — одна программа на Go, `kinodom.exe`. Она работает службой Windows и состоит из трёх частей:
- **HTTP-сервер.** Отдаёт API (`/api/v1/…`), потоки видео и пульт.
- **Модули.** Каждый живёт под сторожем (`internal/supervisor`): упавший модуль перезапускается, остальные работают дальше.
- **Хранилище.** Состояние — в одной базе SQLite: настройки, каталог, реестр раздач, медиатека, история, каналы.
  - Миграции — `internal/store/migrations/NNNN_*.sql`, номера идут подряд.
  - Каждый модуль ходит только в свои таблицы.

Пульт — веб-страницы на ES-модулях без сборки (`web/static`), встроены в exe. Приложение для Android (`android`) показывает тот же пульт во весь экран и добавляет свой плеер каналов.

## Сервер: `cmd/kinodom` и `internal/`

| Пакет | Что делает |
|---|---|
| `cmd/kinodom` | команды: служба, консоль, установка, проверка, ссылки `kinodom://`, значок в трее, проверки вживую |
| `internal/app` | собирает сервер из модулей и связывает их (каталог ↔ торренты ↔ медиатека ↔ подписка), применяет настройки на лету |
| `internal/api` | HTTP-сервер: маршруты модулей, поток видео, пульт. Маршруты бывают: `Handle` — всем; `HandleHome` — только из домашней сети (изменения); `HandleLocal` — только с этого ПК |
| `internal/supervisor` | запуск модулей и перезапуск упавших; состояние модулей — в «Состоянии» |
| `internal/store` | база SQLite, миграции, общие таблицы: настройки, проблемы для «Состояния» |
| `internal/settings` | настройки из пульта: чтение, проверка, запись; приложение применяет их без перезапуска |
| `internal/catalog` | каталог трекеров. Подробнее — ниже |
| `internal/source` | общий вид трекера (`Source`): `rutor`, `rutracker` (API, форум, вход, Cloudflare через `internal/edge`), `jacred` (источник поиска Jacred или Jackett) |
| `internal/kpcat` | каталог «Кинопоиск»: популярные списки сайта по разделам, порядки, оценки IMDb |
| `internal/meta` | Кинопоиск (без ключа — `KPWeb`, с ключом — неофициальный API), рейтинги, разбор названий раздач, кэш картинок |
| `internal/torrents` | торрент-движок (anacrolix/torrent): реестр раздач, загрузка, просмотр во время загрузки, уборка по сроку и по месту |
| `internal/library` | медиатека: обход папок, распознавание, карточки, «Удалить» |
| `internal/follow` | подписка на сериалы: проверка страницы раздачи, переход на новую версию с докачкой серий |
| `internal/iptv` | каналы. Подробнее — ниже |
| `internal/history`, `internal/watch` | история и «Продолжить» по устройствам; место — по чтению потока |
| `internal/discovery` | объявление сервера в сети по SSDP: приложение находит его само |
| `internal/appdist` | раздача приложения для Android (`/app`) |
| `internal/setup`, `internal/winsvc` | установка и удаление: служба, брандмауэр, права на папки, ссылка `kinodom://` |
| `internal/netx` | сеть: прокси из настроек, зеркала трекеров, распознавание отказов |
| `internal/player`, `internal/power`, `internal/tray`, `internal/logx` | плеер на ПК, запрет сна во время просмотра, значок в трее, журнал |

### Каталог трекеров (`internal/catalog`)

- **Обновление.** Разделы обновляются по расписанию: топ раздела по раздающим, у Rutracker — из официального API.
- **Догрузка.** Страницы раздач догружаются в фоне: описание, постер, номер Кинопоиска, формат, magnet и `.torrent`. Раздачи, которые видны в пульте, — первыми.
- **Склейка.** Карточка — фильм, а не раздача: раздачи одного фильма (по номеру Кинопоиска или названию и году) склеиваются, «Другие раздачи» показывают все.
- **Порядки раздела.**
  - Раздающие — место в разделе; глубже первой сотни порции догружаются по мере прокрутки.
  - Качающие, новизна, число скачиваний — списки порядка в памяти: у Rutracker из списка раздела API или поиска форума, у Rutor — из страниц сайта.
- **Поиск** идёт по трекерам и по источнику поиска одновременно.

### Каналы (`internal/iptv`)

- **Пул.** Плейлисты (`m3u`) дают пул источников. Источники сопоставляются с каналами телепрограммы (`xmltv`) по правкам, `tvg-id`, базе iptv-org и названию. Нераспознанное попадает в «Не распознано».
- **Проверка.** `probe` проверяет источники: живы ли и не тормозят ли (лёгкая и полная проверка). Канал предлагает плееру только живые источники.
- **Версии** одного канала по часовым поясам (`+N`, `-plN`) собраны в семейство.
- **Пересылка.** Источник можно посмотреть в пульте через пересылку сервера: только по номеру источника, ссылки внутри списков HLS подписаны.
- **Свои каналы** (`my-N`) собираются из нераспознанных потоков.

## Пульт: `web/static`

- `index.html`, `app.js` — шапка, разбор адреса (`#/catalog/…`), переходы. `nav.js` — управление стрелками пульта ТВ.
- `ui.js` — элементы и общие мелочи: `h()`, форматы чисел, окна подтверждения. `api.js` — запросы к API. `icons.js` — значки.
- `views/*.js` — экраны: каталог, раздача, поиск, загрузки, каналы, медиатека, история, настройки, мастер, «Кинопоиск» (`kpcat.js`), просмотр источника (`preview.js`).
- `vendor/` — hls.js и mpegts.js для просмотра источников каналов, с лицензиями.
- Тесты — сценарии Node в `web/web_test.go`. Чистые функции экранов экспортируются и проверяются там же.

## Приложение: `android`

- Kotlin и Media3 (ExoPlayer). `WebView` показывает пульт сервера.
- Мост `KinodomApp`: версия, обновление с сервера, встроенный или системный плеер каналов, `canPickFiles(тип)` — есть ли на устройстве выбор файла. Пульт в приложении умеет выбирать файлы (`<input type=file>`) и показывать видео во весь экран (WebChromeClient).
- Свой плеер каналов: листание, набор номера, список с передачами.
- Сервер ищется по SSDP или вводится адресом.
- **Сервер на устройстве** (полный порт): тот же сервер собран под android/arm64 — `build.ps1` кладёт его в `jniLibs` как `libkinodomserver.so`, Android распаковывает в `nativeLibraryDir`, откуда приложение запускает его процессом (`LocalServerProcess`). Данные — в `filesDir/kinodom`, пульт — `127.0.0.1:8190`, куча сервера ограничена `GOMEMLIMIT`. Windows-пакеты (служба, трей, Edge, реестр) под `go:build windows`; на Android у них заглушки той же формы. ffprobe/ffmpeg для устройства — `third_party/ffmpeg/build-android.sh` (NDK).

## Установщик: `installer`

Сценарий Inno Setup (`kinodom.iss`) ставит:
- программу;
- службу и правила брандмауэра;
- приложение для Android — его раздаёт `/app`.

При удалении можно стереть и скачанное.
